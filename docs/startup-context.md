# 起動経路によって保存データ・自動起動登録が異なる場合

## 2026-09-16に確認した原因

開発ツールから起動した子プロセスと、エクスプローラーから通常起動したプロセスで、Windowsのファイル・レジストリ仮想化によって参照先が異なっていた。

|確認項目|開発ツール経由|エクスプローラー経由（修復前）|
|---|---|---|
|JSONの論理パス|`%LOCALAPPDATA%\MyShortcutGuide\shortcuts.json`|同左|
|開いたファイルの実体|`%LOCALAPPDATA%\Packages\OpenAI.Codex_2p2nqsd0c76g0\LocalCache\Local\MyShortcutGuide\shortcuts.json`|通常の論理パスどおり|
|読み込んだデータ|4セクション・14件|初期7セクション・0件|
|HKCU RunのMyShortcutGuide値|存在|存在しない|

`GetFinalPathNameByHandle`で実際に開いたファイルのパスを確認し、同じ診断EXEを両方の経路で実行して比較した。表示上のユーザー名・SID・パスが同じでも、参照先が同じとは限らない。今回の診断EXEでは`GetCurrentPackageFullName`が両方とも15700（パッケージなし）を返したため、このAPIだけでは判別できない。

登録データが削除されたのではなく、通常起動時に別領域の初期データを読み込んでいた。また、自動起動の登録は開発ツール側からだけ見えていた。開発ツール経由で起動し直すだけでは、この状態は解消しない。

## 復旧と確認

1. 両方のJSONと既存バックアップ、起動登録を退避する。
2. アプリが終了していることと、復旧先が空データであることを確認する。双方に編集がある場合は単純に上書きせず内容を比較する。
3. 通常のWindows実行コンテキストで、退避した正しいデータを通常保存先へ原子的に置き換える。
4. 同じコンテキストで、現在のEXEの自動起動を登録する。
5. エクスプローラーから起動し、画面・保存ファイル実体・起動登録・生成YAMLを確認する。
6. 実際のWindows再ログインで自動起動を確認する。`--background`の手動実行だけでは、ログイン時に実行されることの証明にはならない。

今回、通常領域への14件の復旧、通常領域のRun登録、バックグラウンド起動、編集画面での14件表示、14件のYAML生成を確認した。実際のWindows再ログインによる確認は未実施。

## 開発・検証時の注意

- インストール済みアプリの最終確認はエクスプローラーなど通常のWindows起動経路で行う。開発ツールの子プロセスとして起動した結果だけで判定しない。
- 自動起動登録を読み書きするシェル自体にも同じ仮想化がかかり得る。シェルからレジストリ値が見えることだけを根拠に正常と判定しない。
- 保存・復旧前に実体パスを確認し、異なる領域に残ったデータは自動同期・削除しない。
- 通常の配布EXEを起動するために、開発ツールやWindowsのセキュリティ設定を変更する必要はない。
